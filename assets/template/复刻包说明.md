# 复刻包说明

这个包只包含 **001–102 段**、从头复刻 TroubleMaker 视频所需的素材和脚本。

- **028、087** 只有黑衣人，没有一号、二号：不写提示词、不生成，组装时直接用原片。
- 其余 **100 段** 需要按简介和 `总体使用规则.md`、`R2VA加强版提示词模板.md` 现写提示词，再提交生成。

## 目录

- `补齐生成用\`：001–102 的源片（文件名带补齐后的帧数）、同名中文简介（028、087 没有）、`原始帧数.txt`（组装时每段保留的帧数）、`补齐后帧数.txt`（第三列是这一段出镜的角色：一号二号／一号／二号／原片）。
- `替换用参考图\`：`一号.png`、`二号.png`。文件名是唯一编号依据，不要按外貌反推。
- `提示词\`：空目录。按简介和模板为 100 段现写。
- `完成分段\`：空目录。生成成功后由 `rh_batch.py` 下载到这里。
- `原片音轨.m4a`：从原 MV 抽出的 AAC 音轨，**已裁掉开头 19.37 秒**（约 199.08 秒），组装时整条替换，直接从头用。
- `rh_batch.py` / `assemble.py` / `validate_prompts.py`：提交、组装、校验。
- `总体使用规则.md` / `R2VA加强版提示词模板.md`：写提示词的规则和模板。
- `ai应用.txt` / `并发数.txt`：模式、实例、一采分辨率、并发数。
- `ffmpeg\`：便携版 ffmpeg/ffprobe。

## 步骤

1. 在包根目录的 `api_key.txt`（空占位）里写入自己的 RunningHub API Key。
2. 写提示词：为 100 段写 `提示词\NNN.txt`，**028、087 不写**。
   按 `补齐生成用\NNN.txt` 的简介、`总体使用规则.md`、`R2VA加强版提示词模板.md` 写；写之前按 24 帧/秒逐帧核对源片。
3. `python validate_prompts.py`，必须 `errors 0`。
4. 提交这 100 段（不要提交 028、087）：

   ```powershell
   python rh_batch.py submit 001 002 003 004 005 006 007 008 009 010 011 012 013 014 015 016 017 018 019 020 021 022 023 024 025 026 027 029 030 031 032 033 034 035 036 037 038 039 040 041 042 043 044 045 046 047 048 049 050 051 052 053 054 055 056 057 058 059 060 061 062 063 064 065 066 067 068 069 070 071 072 073 074 075 076 077 078 079 080 081 082 083 084 085 086 088 089 090 091 092 093 094 095 096 097 098 099 100 101 102
   ```

5. 全部成功后运行：

   ```powershell
   python assemble.py
   ```

   成品在 `完成分段\最终组装\TroubleMaker_final_Made-by-wuwukasi.mp4`，24fps，音轨是 `原片音轨.m4a`（已裁掉开头 19.37 秒）。

## 说明

- 组装会按 `原始帧数.txt` 自动裁掉每段补帧尾巴；028、087 用 `补齐生成用` 的原片，其余用 `完成分段` 的生成段。
- `完成分段` 在生成前是空的；`rh_batch.py` 下载时会创建/写入。缺一段时 `assemble.py` 会停下，不会跳过。
- 如果不带 `ffmpeg` 目录，`assemble.py` 会回退到系统 PATH 里的 ffmpeg/ffprobe。
- 检查/比对/废弃/中间结果、`待修改.md`、`rh_state*.json`、真实 API Key 都不在包里；`rh_state.json` 会在第一次提交时自动创建。
